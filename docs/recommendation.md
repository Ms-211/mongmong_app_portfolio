# 추천 알고리즘

구현 위치: [GameSearchScreen](../lib/screens/game_search_screen.dart). 아래 내용은 현재 코드의 동작 설명이며, 추천 정확도나 사용자 만족도를 측정한 결과가 아닙니다.

## 입력

인원은 필수이고 분위기·난이도·시간은 선택입니다. 선택하지 않은 항목은 '전체'로 전달됩니다.

| 분위기 입력 | 전달 장르 |
| --- | --- |
| 신나는 파티 | 파티 |
| 전략적인 | 전략 |
| 추리/몰입형 | 추리 |
| 협동/팀워크 | 협동 |
| 순발력 | 순발력 |

## 후보 선정

1. 게임 데이터 중 is_active가 참인 게임을 로드합니다.
2. 검색어가 있으면 공백을 제거하고 소문자로 변환한 이름의 부분 일치를 확인합니다.
3. 선택 인원 범위와 게임의 min_player~max_player 범위가 겹치는 게임만 남깁니다.
4. 점수를 계산해 **40점 이상**인 게임을 후보로 삼습니다.

인원 범위는 2인·3인·4인·3~4인·5~6인·7인+를 지원하며, 7인+는 코드에서 7~99로 표현합니다. 5~6인 선택 시 5인만 가능한 게임도 범위가 겹치므로 후보가 됩니다. 모든 인원수에서 플레이 가능해야 한다는 의미는 아닙니다.

## 점수

| 조건 | 점수 |
| --- | ---: |
| is_pick가 참 | +30 |
| recommended_player가 선택 인원 범위 안에 있음 | +30 |
| 선택 장르와 일치 | +30 |
| 난이도 정확히 일치 | +25 |
| 난이도 차이가 1 | +12 |
| 시간 구간 정확히 일치 | +25 |
| 시간 구간 차이가 1 | +10 |

'전체'인 조건은 점수를 추가하지 않습니다. 난이도와 시간은 각각 정확 일치 또는 인접 일치 중 한 가지만 적용합니다. 모든 조건이 정확히 일치하고 PICK인 경우 최대 점수는 140점입니다.

게임 시간은 **max_play_time**을 사용하며, 시간 구간은 다음과 같습니다.

| 구간 | 실제 분 값 |
| --- | --- |
| 0 | 10분 이하 |
| 1 | 10분 초과~20분 이하 |
| 2 | 20분 초과~40분 이하 |
| 3 | 40분 초과~60분 이하 |
| 4 | 60분 초과 |

코드의 선택 라벨은 마지막 구간을 '60분 이상'으로 표시하지만, 점수 계산상 60분은 구간 3에 들어갑니다.

## 결과 정렬

다음 우선순위로 정렬한 뒤 **최대 40개**를 표시합니다.

1. 추천 점수 높은 순
2. PICK 게임 우선
3. 난이도 낮은 순
4. 게임 이름의 Dart 문자열 비교 순

동점에 추가 무작위 정렬은 적용하지 않습니다.

## 계산 예시

사용자가 4인·전략·난이도 3·20분~40분을 선택한 경우:

| 게임 조건 | 계산 | 결과 |
| --- | --- | --- |
| 2~4인 가능, 추천 4인, 전략, 난이도 3, 최대 30분, PICK | 30 + 30 + 30 + 25 + 25 | 140점 |
| 2~6인 가능, 추천 5인, 전략, 난이도 4, 최대 50분, 일반 | 0 + 0 + 30 + 12 + 10 | 52점 |
| 최대 3인 가능 | 선택 인원과 겹치지 않음 | 점수 계산 전 제외 |

## 일반 검색과의 차이

일반 검색은 인원·난이도·장르·시간 필터의 교집합을 표시합니다. 추천은 실제 플레이 가능 인원을 후보 제한으로 사용하고, 나머지 조건은 점수에 반영합니다. 따라서 추천 결과에 선택 장르나 난이도가 정확히 일치하지 않는 게임이 포함될 수 있습니다.

일반 검색의 인원 필터는 recommended_player 기준이므로, 플레이는 가능하지만 추천 인원이 다른 게임은 제외될 수 있습니다.

## 경계 조건과 개선 과제

- **인원만 선택한 경우:** 일반 게임은 추천 인원까지 맞아도 30점이므로 40점 기준에 못 미칩니다. 현재 이 경우 결과에 포함되려면 PICK이면서 추천 인원도 맞아야 합니다. 결과 부족 시 기준을 완화하는 fallback은 없습니다.
- **시간 문자열 차이:** 일반 검색의 40~60분 조건 문자열은 '40~60분', 추천 질문과 점수 계산의 문자열은 '40분~60분'입니다. 필터를 변경하는 흐름에서는 표현과 매핑의 일관성을 확인해야 합니다.
- **60분 경계:** 일반 검색은 40분 초과~60분 이하와 60분 이상 조건에 60분을 포함하지만, 추천 구간 계산은 60분을 구간 3으로 취급합니다.
- **데이터 품질:** 잘못된 숫자가 Model에서 0으로 바뀌면 후보 선정과 점수에 영향을 줄 수 있습니다.
- **검증 범위:** 현재 저장소에 추천 계산 단위 테스트나 실제 사용자 평가 자료는 없습니다.

추가할 테스트는 플레이 불가능 인원 제외, 구간 교집합, 난이도·시간의 인접 점수, 40점 경계, 동점 정렬, 40개 제한, 인원만 선택했을 때의 결과를 우선 대상으로 삼을 수 있습니다.
